# 汽车保养平台功能实现对照

依据仓库内《Java企业级项目实践任务书及计划书+2023T计算机》的“汽车保养平台的设计与实现”功能要求，核对默认分支已有代码并补齐业务入口。此次实现沿用 Spring Boot、MyBatis、MySQL 与 Vue 3，权限和数据库事务由后端负责。

## 新增接口

| 方法 | 路径 | 权限及用途 |
| --- | --- | --- |
| GET | `/api/store/profile` | 门店账号，取得自身资料并生成登记链接 |
| POST | `/api/stores/{storeId}/check-ins` | 用户账号，登记自己的已确认预约 |
| GET | `/api/store/orders/lookup-appointments?code=12345678` | 门店账号，仅返回该门店凭据对应的预约 |
| POST | `/api/product-reviews` | 用户账号，对已完成订单内的商品评价 |
| GET | `/api/product-reviews` | 用户账号，查看自己的商品评价 |
| GET | `/api/products/{productId}/reviews?page=0&size=20` | 公开分页浏览商品评价 |

到店登记请求体：

```json
{ "appointmentId": 1, "verificationCode": "12345678" }
```

商品评价请求体：

```json
{ "orderId": 1, "productId": 1, "rating": 5, "content": "配件质量很好" }
```

登记二维码指向 `/?checkInStore={门店ID}#check-in`。用户登录后页面仅加载自己的预约，后端再次验证用户、预约、订单、门店和核销码。核销和登记记录处于同一事务；登记失败时不会遗留单独核销的订单。已登记的预约不可再取消，重复登记返回已有结果。

每个订单的每种商品只能评价一次，数据库唯一约束覆盖并发重复提交；门店评价与商品评价分别保存。只购买同一商品多件时，仍作为同一订单商品评价。

## 库存与数据库升级

新订单保存价格快照并检查库存，不占用库存；平台配送时重新检查实际库存，以原子更新扣减，任何商品不足均使整个配送事务回滚。因此多个待配送订单可能购买同一库存，最终能否配送以配送时库存为准，管理员可补货后重试。

初始化脚本可用于已有数据卷的增量升级：

- 增加 `appointments.checked_in_at` 记录到店时间。
- 增加 `orders.stock_deducted` 区分新订单与旧版本已扣库存订单。
- 新增 `product_reviews`，为评分范围、购买关联和重复评价添加约束。
- 旧版本已扣库存的待审核/待配送订单在配送时不重复扣库存；旧待审核订单被拒绝时返还库存。
- 旧版本已拒绝订单的遗留库存通过事务返还并更新标记；重复执行不会重复返还。

导入方法和手机访问配置见根目录 README。导入前停止后端，导入完成后再启动。此次代码编辑没有连接或修改实际 MySQL 数据卷。

## 回归用例与验证状态

已有 MySQL 集成测试补充了以下场景：

- 下单不扣库存、配送扣库存、重复配送不再扣减。
- 多商品配送中一个商品不足时，前面商品的扣减回滚，订单保留待配送状态。
- 新订单被拒绝不改变库存；旧订单的已扣库存只恢复一次。
- 未确认预约、他人预约、错误核销码不能登记；失败后订单与登记时间保持原状。
- 同一订单不能重复创建有效预约；登记后不能取消，重复登记可以返回已有结果。
- 商品评价成功、重复评价、评价未购买商品、评价他人订单与公开读取。
- 数据库基础结构包含新增商品评价表。

多商品回滚用例使用真实请求事务，并在结束时只清理该用例创建的数据，避免外层测试事务掩盖真实回滚结果。
